## What landed

1. **`bdcc837` — per-operator Herdr presentation lock namespace.**
   `/tmp/firstmate-herdr-presentation` was a fixed, uid-less path created mode 700.
   On a multi-operator box the first operator to create it owns it outright, and
   every other operator's ownership validation then fails permanently.
   Present in kun's production `main` too, so the fix is upstream-worthy.
   Impact was uneven: `fm-teardown` and `fm-herdr-session-cleanup` warn and skip
   (leaking a pane or an orphan), a fresh projected spawn falls back flat with a
   warning, but the projected **resume** path in `fm-spawn.sh` exits 1 outright.
   Fixed by carrying the operator's uid. A Herdr session socket is per-operator
   already, so no mutual exclusion is lost.
   Verified on a live 3-operator box (uids 1001/1003/1004) where the uid-less
   directory was already owned by another operator.

2. **`49d7ff6` — consolidation merge.**
   Brought berths (`bin/fm-berth.sh`), derived crew names (`bin/fm-name.sh`),
   per-berth Herdr workspace labels, and the lock fix onto the trunk. Zero conflicts.

3. **Two intentional `SC2016` sites annotated.**
   Both feed a literal `'$(id)'` to a name validator to prove an unexpanded command
   substitution is rejected. These had been failing the pinned ShellCheck 0.11.0
   gate since the berth work was written — on every branch carrying it.

## Open blocker — diagnose this first

`tests/fm-backend-herdr-presentation-e2e.test.sh` fails:

```
not ok - concurrent post-create abort cleanup interleaved outside the presentation lock
```

This runs against the **real** Herdr binary (`family=real-herdr-gated`), not a fake.

Why it matters: before the lock fix the lock never resolved on a shared box, so
every presentation path fell back flat and this assertion could not genuinely
execute there. The fix turned the path on for the first time and it fails.

Two possibilities, not yet distinguished:

- a real ordering defect in the post-create abort cleanup path, previously masked
  by the broken lock (most likely — the surrounding contention tests pass), or
- the lock fix itself is subtly wrong.

Start by checking whether the abort-cleanup path in `bin/fm-spawn.sh`
(`spawn_abort_cleanup`, `HERDR_PROJECTION_ABORT_*`) acquires the presentation lock
at all, or only the task lock. The test name asserts it should.

## Traps that cost this session time

- **Never read a gate's exit code through a pipe.** `bin/fm-lint.sh | tail` reports
  `tail`'s status, always 0. This masked a genuinely failing lint gate for most of
  the session. Use `bin/fm-lint.sh >/dev/null 2>&1; echo $?`.
- **`bin/fm-test-run.sh` requires a selector.** With no argument it exits 2 as a
  usage error, easy to misread as a passing run. Use `--all`.
- **The primary checkout is parked on `fleet-integrated` and is misleading.** Its
  uncommitted berth files are an *older* duplicate of what is committed on
  `fm/berths-and-crew-names`: its harness stub is a shell script, which
  `fm_harness_pid_alive` correctly rejects because it matches `ps -o comm=`. The
  committed version copies a real executable. Left in place, not discarded.
- `~/.claude/jobs/c4a6ad9b/tmp/ship/tests/zz-pristine-herdr.test.sh` is untracked
  scratch from an earlier session. Deliberately not committed.
- Auditing branches with `git cherry` against the **wrong** trunk reports every
  commit as new and is silently useless. Verify the trunk contains what you expect
  (check for a known fork-only file) before trusting an audit.
